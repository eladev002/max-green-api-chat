# MAX Chat — веб-клиент мессенджера MAX на GREEN-API

Тестовое задание на должность «Фронтенд разработчик React»: интерфейс для
отправки и получения текстовых сообщений через сервис
[GREEN-API](https://green-api.com/) по HTTP API.

Приложение целиком клиентское: пользователь вводит данные своего инстанса,
создаёт чат по номеру телефона, отправляет сообщение и видит ответ
собеседника — без перезагрузки страницы.

## Быстрый старт

Требуется Node.js 18+ (проверено на Node 22).

```bash
# 1. Установить зависимости
npm install

# 2. Запустить dev-сервер
npm run dev
```

Откройте <http://localhost:5173> и введите данные инстанса из личного кабинета
GREEN-API: `idInstance` и `apiTokenInstance`.

> **Важно:** инстанс должен быть авторизован — то есть QR-код отсканирован в
> приложении GREEN-API (вкладка «Инстанс» в кабинете). Пока инстанс не
> авторизован, `getSettings` вернёт ошибку и вход не пройдёт.

### Продакшен-сборка

```bash
npm run build     # tsc --noEmit && vite build -> dist/
npm start         # статика из dist/ + прокси /green-api на порту 8081
```

`npm start` поднимает `server/proxy.mjs`: он раздаёт собранное приложение и
проксирует запросы к GREEN-API с того же origin (см. [про CORS](#про-cors-и-прокси)).

## Как это работает

1. **Вход.** Пользователь вводит `idInstance` и `apiTokenInstance`. Пара
   проверяется запросом `getSettings`; при ошибке показывается понятное
   сообщение (неверный токен, неавторизованный инстанс и т. д.). Данные
   сохраняются в `localStorage` и при следующем открытии проверяются повторно.
2. **Новый чат.** Номер телефона нормализуется в `chatId` вида
   `79991234567@c.us` (принимаются `+7 999 123-45-67`, `89991234567`,
   `9991234567`). Создаётся локальная переписка.
3. **Отправка.** `sendMessage` — с оптимистичным отображением: сообщение
   появляется сразу со статусом «отправляется», после ответа API получает
   реальный `idMessage`, а при ошибке помечается как неудачное с кнопкой
   «Повторить».
4. **Получение.** Фоновый long-poll `receiveNotification` (таймаут 20 с)
   забирает уведомления из очереди, каждое подтверждается
   `deleteNotification`, после чего текст сообщения попадает в нужную
   переписку и счётчик непрочитанных.
5. **Интерфейс.** Двухпанельный layout: список чатов слева, переписка справа;
   статус соединения — в подвале сайдбара.

## Используемые методы GREEN-API

Базовый шаблон запроса:
`{apiUrl}/waInstance{idInstance}/{method}/{apiTokenInstance}`

| Метод | Запрос | Назначение |
| --- | --- | --- |
| `getSettings` | `GET …/getSettings/{token}` | проверка пары `idInstance` + `apiTokenInstance` при входе |
| `sendMessage` | `POST …/sendMessage/{token}` | отправка текстового сообщения (`{ chatId, message }` → `{ idMessage }`) |
| `receiveNotification` | `GET …/receiveNotification/{token}?receiveTimeout=20` | long-poll: получение входящих уведомлений; пустая очередь → `null` |
| `deleteNotification` | `DELETE …/deleteNotification/{token}/{receiptId}` | обязательное подтверждение обработки уведомления |

Обрабатываются только текстовые сообщения: уведомления с
`typeWebhook: incomingMessageReceived` и `messageData.typeMessage: textMessage`
(а также `outgoingMessageReceived` — сообщения, отправленные с телефона).
Уведомления остальных типов (статусы доставки, набор текста, звонки, изменение
состояния инстанса, медиафайлы) корректно игнорируются, чтобы интерфейс не
ломался. Документация: <https://green-api.com/docs/api/>.

## Про CORS и прокси

Публичный хост `api.green-api.com` **не возвращает CORS-заголовки**, поэтому
браузерный запрос к нему напрямую блокируется политикой same-origin. Проверено
запросом `OPTIONS`/`GET` — ответ `403` без `Access-Control-Allow-Origin`.

Поэтому приложение по умолчанию обращается не напрямую, а по относительному
пути `/green-api`:

- **в dev** его проксирует Vite (`server.proxy` в `vite.config.ts`);
- **в продакшене** — `server/proxy.mjs`, который раздаёт статику и проксирует
  API с того же origin.

Если ваш инстанс доступен напрямую (или вы используете собственный прокси),
укажите адрес в форме входа в блоке «Настройки подключения» либо задайте
`VITE_GREEN_API_BASE_URL=https://api.green-api.com`.

## Переменные окружения

Скопируйте `.env.example` в `.env` (файл не обязателен — все значения имеют
разумные значения по умолчанию).

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `VITE_GREEN_API_BASE_URL` | `/green-api` | базовый адрес API для браузера (через прокси) |
| `VITE_GREEN_API_RECEIVE_TIMEOUT` | `20` | таймаут long-poll в секундах (допустимо 5–60) |
| `VITE_GREEN_API_ID_INSTANCE` | — | предзаполнение формы входа |
| `VITE_GREEN_API_TOKEN_INSTANCE` | — | предзаполнение формы входа |
| `GREEN_API_PROXY_TARGET` | `https://api.green-api.com` | куда проксировать `/green-api` |
| `PORT` | `8081` | порт прод-прокси |
| `PUBLIC_DIR` | `dist` | каталог со сборкой |

### Тесты

`npm test` прогоняет 9 проверок на чистых функциях: разбор уведомлений
GREEN-API (примеры JSON взяты из документации) и нормализация телефонных
номеров. Тесты запускаются встроенным в Node тест-раннером — дополнительных
зависимостей нет, файлы предварительно собираются `esbuild`.

## Проверка сценария из задания

1. Откройте приложение и введите `idInstance` и `apiTokenInstance` → «Войти».
2. В сайдбаре введите номер телефона получателя → «Начать».
3. Напишите сообщение и нажмите Enter — оно появится справа со статусом
   отправки и временем.
4. Получатель отвечает в MAX — ответ появится слева **автоматически**, без
   перезагрузки страницы (в сайдбаре этому чату добавится счётчик
   непрочитанных, если он не открыт).
5. Чтобы проверить приём, можно написать приложению с другого телефона на
   номер, привязанный к инстансу.

## Известные ограничения

- **Только текст.** Вложения, голосовые и кнопки не поддерживаются — по
  условиям задания. Входящие нетекстовые сообщения не отображаются, чтобы не
  показывать пустые пузыри.
- **Токен в браузере.** Схема GREEN-API требует передавать
  `apiTokenInstance` в URL, поэтому он виден пользователю. Для реального
  продукта нужен бэкенд, который держит токен у себя; прокси
  `server/proxy.mjs` — минимальный вариант для демонстрации.
- **Очередь уведомлений.** Приложение забирает уведомления из очереди
  GREEN-API, поэтому сообщения, полученные при закрытой странице, не
  потеряются: они останутся в очереди (хранится 24 часа) и будут получены при
  следующем открытии.
- **История.** Переписка хранится в `localStorage` браузера и не
  синхронизируется между устройствами — метод получения истории сообщений в
  задании не указан.
